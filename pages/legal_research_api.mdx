# Legal Research API

There is a single endpoint for the Legal Research API. Given a legal question (and optional attached files) it streams back a draft answer together with all source documents relevant to that question.

The endpoint uses **Server-Sent Events (SSE)** — a `POST` triggers the stream and individual JSON objects are pushed as they are computed, so the UI can display intermediate results immediately without waiting for the full answer.

## Endpoint

```
POST https://api.omnilex.ai/legal-research/:type/combined
```

`:type` is a path segment that controls the run mode:

| Value | Description |
|---|---|
| `app` | Normal production run |
| `demo` | Demo / debug run |

### Headers

| Header | Value |
|---|---|
| `Content-Type` | `application/json` |
| `Authorization` | `Bearer <token>` |

## Request body — `QueryPayload`

```typescript
export interface QueryPayload {
  thread: OmnilexResultThread;
  projectId?: string; // Optional; falls back to user's default project
}
```

### `OmnilexResultThread`

```typescript
export type OmnilexResultThread = {
  id?: string;            // Omit or leave empty to create a new thread
  date: Date;
  ownerUsername: string;  // Must match the authenticated user's email for follow-ups
  projectId?: string;

  can_read: string[];
  can_write: string[];

  errors?: SerializableError[];
  status: 'PROCESSING' | 'COMPLETED' | 'ERROR';

  type: 'thread';
  thread: Thread;
};
```

### `Thread`

```typescript
export interface Thread {
  id?: string;
  date: Date;
  ownerUsername: string;
  status?: 'PROCESSING' | 'COMPLETED' | 'ERROR';
  interactions: Interaction[];
  errors?: SerializableError[];
}
```

### `Interaction`

The API always answers the **last** interaction in the array, using previous ones as conversation context.

```typescript
export interface Interaction {
  // ── Required ──────────────────────────────────────────────
  id: string;
  date: Date;
  question: string;
  countries: Country[];   // Jurisdiction(s) to search in

  // ── Optional input ────────────────────────────────────────
  documents?: OmnilexFile[];
  inputSelectedSources?: InputSelectedSources; // Filter which sources to search
  flowKey?: string;       // Which flow to run (defaults to 'default')
  assistantId?: string;   // Resource ID of a configured assistant (overrides flowKey)
  systemPrompt?: string;  // Custom system prompt override

  // ── Output (set by the API, send empty values) ─────────────
  sources: ConsiderationDetails[];
  reply: string;
  followupProposals?: string[];
  progressSteps?: ResultProgress[];
}
```

## SSE Event stream

Each event is a JSON object sent as a standard SSE `data:` line. The `type` field discriminates the event. Every event also carries:

- `groupingKey` — which UI group it belongs to (`"default"` or `"reasoning"`)
- `eventId` — the thread ID (injected automatically by the server)

```
data: { "type": "...", ...fields }\n\n
```

### Event reference

#### `status` — lifecycle markers

The very **first** and very **last** events are always `status` events.

```typescript
// First event
{ type: 'status', status: 'start', resultId: string }

// Last event (success)
{ type: 'status', status: 'end', resultId: string }

// Last event (error)
{ type: 'status', status: 'error', error?: string }
```

> `resultId` is the ID of the thread stored in the database — use it for follow-up requests.

---

#### `omnilex-result` — full thread snapshot

Sent **twice**: once immediately after the thread is created (so the UI can display the shell) and once at the very end with the completed answer.

```typescript
{ type: 'omnilex-result', omnilexResult: OmnilexResultThread }
```

---

#### `delta` — streaming answer chunks

Concatenate all `delta` strings in order to reconstruct the final draft answer.

```typescript
{ type: 'delta', delta: string }
```

---

#### `consideration` — source documents

Contains the `ConsiderationDetails` objects found during the research. May be emitted multiple times as more sources are retrieved. The final complete list is also available on `omnilexResult.thread.interactions[last].sources`.

```typescript
{ type: 'consideration', considerations: ConsiderationDetails[] }
```

For the full `ConsiderationDetails` type reference see `consideration-details.md`.

---

#### `search` / `search-results` — search progress

Emitted while the agent is searching a specific source type.

```typescript
{ type: 'search', considerationType: ConsiderationType }
{ type: 'search-results', considerations: ConsiderationDetails[] }
```

---

#### `fetch` / `fetch-results` — fetch progress

Emitted while the agent is fetching the full content of sources.

```typescript
{ type: 'fetch', considerationType: ConsiderationType }
{ type: 'fetch-results', considerations: ConsiderationDetails[] }
```

---

#### `message` — human-readable progress messages

Status messages intended for display in the UI while the user waits (e.g., "Searching legal sources", "Reading 5 sources").

```typescript
{ type: 'message', message: string }
```

Common messages are localised; see `ReasoningMessageTranslations` in `result-progress.types.ts`.

---

#### `followups` — suggested follow-up questions

```typescript
{ type: 'followups', followups: string[] }
```

---

#### `group-start` / `group-end` — progress grouping

Used to visually group related progress events in the UI.

```typescript
{ type: 'group-start', groupingKey: 'default' | 'reasoning' }
{ type: 'group-end',   groupingKey: 'default' | 'reasoning' }
```

---

#### `question` — interactive clarification (ask_question flow only)

The agent may pause to ask the user a clarifying question before proceeding. The UI must send the answer back as a follow-up interaction.

```typescript
// Single question
{
  type: 'question';
  toolCallId: string;
  reasoning: string;
  question: string;
  suggestedAnswers: string[];
  multiSelect?: boolean;
}

// Multi-question
{
  type: 'question';
  toolCallId: string;
  reasoning: string;
  questions: {
    id: string;
    label: string;
    question: string;
    suggestedAnswers: string[];
    multiSelect?: boolean;
  }[];
}
```

## `InputSelectedSources` — filtering sources

By default, Omnilex searches all resources the user has access to. Use `inputSelectedSources` on an `Interaction` to restrict the search to specific categories.

> Permission check: even if a source is listed here, it will only be searched if the user has permission to access it.

```typescript
export interface InputSelectedSources {
  selectedSources: SelectedSource[];
}

export type SelectedSource =
  | InternalDataSource
  | ArticlesSource
  | CourtDecisionsSource
  | OmnilexCommentariesSource
  | KoordinationSource
  | WebsitesSource
  | EULawsSource
  | ZefixSource
  | StaempfliSource
  | SwissregSource
  | ComputerUseSource;
```

## Linking citations in the answer to sources

The answer text always uses the exact `citation` string from the matching `ConsiderationDetails` object. The simplest way to create hyperlinks is to iterate over `considerationDetails` and run a regex / string search against the answer text.

## Examples

### TypeScript client (using `sse.js`)

```typescript
import { SSE } from 'sse.js';
import type { ResultProgress } from '@shared/types/result-progress.types';
import type { QueryPayload } from '@shared/dtos/legal-research.dto';

const ENDPOINT = 'https://api.omnilex.ai/legal-research/app/combined';
const email = 'user@example.com';

const payload: QueryPayload = {
  thread: {
    date: new Date(),
    ownerUsername: email,
    can_read: [],
    can_write: [],
    status: 'COMPLETED',
    type: 'thread',
    thread: {
      date: new Date(),
      ownerUsername: email,
      interactions: [
        {
          id: '0',
          date: new Date(),
          countries: ['CH'],
          question: 'I had an accident with an e-scooter in Zug. How should I reply to this letter?',
          documents: [],
          sources: [],
          reply: '',
        },
      ],
    },
  },
};

const source = new SSE(ENDPOINT, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer <token>',
  },
  payload: JSON.stringify(payload),
});

let answer = '';

source.addEventListener('message', (e: { data: string }) => {
  const event: ResultProgress = JSON.parse(e.data);

  switch (event.type) {
    case 'status':
      if (event.status === 'start') console.log('Stream started. Thread ID:', event.resultId);
      if (event.status === 'end')   console.log('Stream finished.');
      if (event.status === 'error') console.error('Error:', event.error);
      break;

    case 'delta':
      answer += event.delta;
      break;

    case 'consideration':
      console.log('Sources received:', event.considerations.length);
      break;

    case 'message':
      console.log('Progress:', event.message);
      break;

    case 'followups':
      console.log('Suggested follow-ups:', event.followups);
      break;

    case 'omnilex-result':
      console.log('Thread snapshot:', event.omnilexResult.status);
      break;
  }
});
```

### Follow-up question (chat mode)

To ask a follow-up, resend the thread with the same `id` and append a new interaction. The API uses all previous interactions as context and answers only the last one.

> If `thread.id` is missing/empty or `ownerUsername` does not match the authenticated user, a brand-new thread is stored instead of updating the existing one.

```typescript
const previousThread: OmnilexResultThread = { /* ... result from previous call ... */ };

const followUpPayload: QueryPayload = {
  thread: {
    ...previousThread,
    thread: {
      ...previousThread.thread,
      interactions: [
        ...previousThread.thread.interactions,
        {
          id: String(previousThread.thread.interactions.length),
          date: new Date(),
          countries: ['CH'],
          question: 'Can you elaborate on the liability aspects?',
          documents: [],
          sources: [],
          reply: '',
        },
      ],
    },
  },
};
```

### Using a configured assistant

Pass the `assistantId` of a configured `OmnilexResourceAssistant` resource. This overrides `flowKey`, applies the assistant's system prompt, model, and knowledge files automatically.

```typescript
interactions: [
  {
    id: '0',
    date: new Date(),
    countries: ['CH'],
    question: 'Draft a reply to this cease-and-desist letter.',
    assistantId: 'resource-uuid-of-assistant',
    documents: [],
    sources: [],
    reply: '',
  },
],
```

## Breaking changes vs. previous API version

| Area | Old | New |
|---|---|---|
| **Endpoint path** | `/advice/app/combined` | `/legal-research/:type/combined` |
| **SSE event shape** | Top-level keys (`response`, `considerationDetails`, `legalArea`, …) | All events use a `type` discriminant field |
| **Streaming answer** | `{ response: "…" }` (last chunk ends with `<AILEGIS-END>`) | `{ type: 'delta', delta: "…" }` (no sentinel string) |
| **Source documents** | `{ considerationDetails: […] }` | `{ type: 'consideration', considerations: […] }` |
| **Legal area** | `{ legalArea: "…" }` | `{ type: 'message', message: "…" }` (merged into general progress messages) |
| **Final result** | `{ result: OmnilexResultThread }` | `{ type: 'omnilex-result', omnilexResult: OmnilexResultThread }` |
| **Thread ID event** | `{ resultId: "…" }` | `{ type: 'status', status: 'start', resultId: "…" }` |
| **Error event** | `{ error: "…" }` | `{ type: 'status', status: 'error', error: "…" }` |
| **Country support** | AT missing | `AT` (Austria) added |
| **Source filter `InternalDataSource`** | `{ id: 'internal-data' }` | Full metadata object with `resourceId`, `databaseName`, `files`, `folders` |
| **New source filters** | — | `EULawsSource`, `ZefixSource`, `StaempfliSource`, `SwissregSource`, `ComputerUseSource` |
| **`QueryPayload`** | `{ thread }` | `{ thread, projectId? }` |
| **`Interaction` input** | — | `flowKey?`, `assistantId?`, `systemPrompt?` added |
| **`Interaction` output** | — | `followupProposals?`, `progressSteps?` added |
